# SX-026 · Valispace summary

## 用途

Valispace 于 **2023-06-20** 发布这篇文章。它把 Muratore 2012 演讲、Michael Jastram / Joe Justice 的观点和 Valispace 自己的产品叙述混合在一起，适合做快速导读，不适合作为独立 SpaceX 证据。

## 可以安全使用的部分

文章正确抓到了 Muratore 原始材料中的几条主线：

- “Tools not Rules”；
- “Test rigorously and often”；
- 低层设计参数可以动态 trade；
- integration / integration testing 在这种组织里仍然重要。

这些内容应优先回引 **SX-002**，而不是把 SX-026 算成第二份独立证据。

## 高风险断言

文章还写到：

- SpaceX 使用 Jama / Valispace 等协作工具；
- SpaceX “没有传统 product manager / project manager / architect”；
- Musk 系公司用 “AI software stacks” 替代管理层。

这些说法在文章中没有提供足够的一手 SpaceX 证据，且部分明显带有软件厂商的产品叙事。**本 Handbook 不把它们当事实使用。**

## 不能据此推出

- 不能因为 Valispace 写了某工具，就断言 SpaceX 实际部署了该工具。
- 不能把 Joe Justice / 作者的概括写成 SpaceX 正式组织设计。
- 不能把对 Muratore 的二次改写当成比 2012 原始材料更强的证据。

## 使用规则

> **只做教学导航。遇到具体 SpaceX 主张，回到 SX-002 或其他一手材料。**

## 回填章节

一般不直接进入正文；可作为 04 Systems / 06 Testing 的延伸阅读。
