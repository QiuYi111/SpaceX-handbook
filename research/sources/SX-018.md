# SX-018 · Tim Berry on The Algorithm

## 为什么重要

Aviation Week 于 **2024-08-23** 发布这篇报道。Tim Berry 在 SpaceX 工作约十年，做过 Falcon 9 / Falcon Heavy 上面级生产、Dragon 集成和增材制造。文章保留了他对 The Algorithm 的逐步解释，因此比只引用二次总结更有价值。

## 证据等级怎么读

这份材料标为 **P1/P2**，因为同一篇文章混合了两类证据：

- Berry 对自己在 SpaceX 经历和 The Algorithm 的直接引语：按第一人称经验使用，接近 P1；
- 记者对 Raptor 3、SpaceX 公布参数和 Musk 社交媒体内容的整理：属于媒体转述，按 P2 使用，重要数字最好再回到 SpaceX 原始发布。

不要把整篇文章统一当成“SpaceX 官方制度文件”。

## 原文定位

### 开头与五步定义

文章先交代 Berry 的 SpaceX 经历，然后记录他在 2024 AIAA Aviation Forum 的说法：The Algorithm 被反复灌输，并用于让设计更容易制造、持续优化。

随后逐步给出：

1. challenge requirements；
2. delete a part or process；
3. simplify / optimize；
4. go faster；
5. automate。

Berry 特别强调顺序：很多组织直接从自动化开始，结果只是把本来不该存在的流程自动化。

### 删除为何影响整个 value chain

Berry 对第二步的解释不是“BOM 少一项”这么简单。他把删除放到 full value chain 上看：去掉不必要的 part / process step，可以同时减少 labor、cycle time 等系统成本。

### go faster 与制造吞吐

第四步的例子直接涉及增加 station、ramp manufacturing。这里的“快”不是只催个人工作，而是改变生产系统容量。

### 循环而不是一次性 checklist

第五步自动化完成后还要重新回到第一步，继续找新的 requirement、part、process 和速度瓶颈。因此更稳妥的理解是持续循环，而不是一次 workshop。

### Raptor 3 案例

报道把 Raptor 3 作为“简化设计 + 简化制造”的案例：外部 plumbing / wiring 被进一步集成进发动机结构。这里属于 Aviation Week 对 SpaceX 公布信息的报道，不应与 Berry 的第一人称流程说明混成同一证据等级。

## 能证明什么

- Berry 明确把 The Algorithm 描述为自己在 SpaceX 被反复训练使用的方法。
- 五步顺序及“不要先自动化坏流程”的解释有直接引语支持。
- 删除零件/工序的价值可以延伸到 labor、cycle time 和制造吞吐。
- go faster 包括生产系统层面的提速，而不只是个人加班。
- 这套方法被 Berry 描述为循环过程。

## 不能据此推出

- Aviation Week 的文章不是 SpaceX 官方流程文件。
- Berry 的经历覆盖多个项目，但不能证明所有团队、所有时期执行方式完全一致。
- Raptor 3 的具体数字和结构描述如果用于技术结论，应继续追 SpaceX 原始发布，而不是只依赖本文。
- The Algorithm 不能被解释为删除法规、安全或已经证明必要的验证。
