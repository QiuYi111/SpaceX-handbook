“SpaceX 什么都自己做”是一种神话化表达。

真正值得学的是：

> **Make / Buy 是系统工程 trade，不只是采购价格比较。**

## 1. SpaceX 到底有多“内制”

2026 S-1/A 把 extreme vertical integration 写成公司核心优势，并明确说内部设计制造的范围包括 engines、avionics、structures、software，甚至“tools that make the tools”。{{< source "SX-001" >}}

同一份申报材料还给出一个少见的具体数字：**SpaceX 自报 Starship 约 80% 为内部制造。**{{< source "SX-001" >}}

这个数字很有价值，但边界也要写清楚：

- 这是 SpaceX 的证券申报口径，不是独立第三方拆解；
- 它说的是 Starship，不代表所有 SpaceX 产品都是 80%；
- S-1/A 中“迭代以周计、传统公司以年计”等比较，也是公司的自我判断，不能去掉主语后写成行业定论。{{< source "SX-001" >}}

因此我们能可靠得到的结论不是“SpaceX 80% 都自研”，而是：

> **SpaceX 确实长期选择了远高于传统航空航天常见水平的内部设计制造，并把这种选择与迭代速度、成本和质量控制直接联系起来。**

Muratore 2012 的材料给出更早期的系统原因：减少 contract/subcontract 边界，可以让关键设计参数之间的 trade 更快。{{< source "SX-002" >}}

NASA COTS 观察补充了经济原因：某些部件外部采购价格高，而内部制造还能改善进度控制和变更速度。{{< source "SX-003" >}}

## 2. 垂直整合真正购买的是什么

最浅的理解是：

> 自己做，单价更低。

但 SpaceX 的一手自述更强调另一件事：内部设计制造让团队能够更快 test、fail、iterate。{{< source "SX-001" >}}

Garrett Reisman 比较 NASA 与 SpaceX 时也给了类似解释：SpaceX 能够快速做决定、发现错了再改，很大程度因为 design 到 development 的链条更内部化，改变方向成本更低。{{< source "SX-023" >}}

因此 vertical integration 购买的不只是零件，而是：

- **等待时间更短**：不用排供应商队列；
- **改动成本更低**：设计变更不必跨多层合同边界；
- **问题信息更完整**：设计、工艺、测试数据离工程师更近；
- **错误更可逆**：发现方向错了，还有能力快速换方向；
- **关键能力不外包**：产品差异化不会完全锁在供应商手里。

一句话：

> **它在购买 optionality，也在购买更短的物理反馈环。**

## 3. Make / Buy 应该比较什么

不要只问：

> 外购单价 vs 自制单价？

至少同时算四类成本：

### 采购成本

- 单价；
- MOQ；
- NRE；
- 模具、治具、运输和库存。

### 等待成本

- 第一次样品多久？
- 改一次图多久？
- supplier queue 多长？
- 出一次异常，多久能拿到下一版？

### 变更成本

- 小修改是否要重新报价、重新排期？
- 供应商愿不愿意做低数量、高频 revision？
- 接口变化会不会触发多家公司联动？

### 信息损失成本

- 缺陷能否快速 root cause？
- 能否拿到 process detail 和原始数据？
- 关键 know-how 会不会被锁在外面？
- 这个部件是否决定系统学习速度？

这四类是**我们的迁移框架**，不是 SpaceX 官方表格。它只是把前述证据转成可执行的 Make / Buy 问题。

## 4. Tom Mueller：控制 cost、schedule、quality

Tom Mueller 后来创办 Impulse Space 时仍然把 vertical integration 当作核心差异，理由很直接：更紧地控制 cost、schedule、service quality。{{< source "SX-016" >}}

这说明它不是 SpaceX 某一个年代的临时习惯，而是早期核心工程领导者认为值得迁移的方法。

但这仍然不等于“越内制越好”。控制力只有在内部团队真的具备相应能力时才有价值。

## 5. 什么东西最值得内制

优先考虑：

### 高频迭代件

每周都要改，外包会把反馈环拉长。

### 系统核心 know-how

决定产品差异化，而且后续版本仍会持续演进。

### 市场供应差

供应商少、lead time 长、价格离谱，或者成熟供应商根本不愿意配合小批量迭代。

### 质量定位关键

失败时必须拿到 process detail，黑盒供应会显著拖慢定位。

### 制造本身就是产品能力

例如独特焊接、测试、精密装配、自动化工装。SpaceX 在 S-1/A 里甚至把制造工具本身纳入内部能力。{{< source "SX-001" >}}

## 6. 什么不值得内制

- 成熟标准件；
- 不影响迭代速度；
- 市场供应非常充分；
- 内部做反而质量更差；
- 需要巨额 CAPEX，但不是核心能力；
- 量太小，学习曲线永远起不来；
- 外部供应商已经能提供足够短的反馈环和足够透明的数据。

垂直整合的目标不是“纯血”，而是系统最优。

## 7. 一个反例：自研成瘾

创业公司很容易说：

> “SpaceX 都自己做，我们也自己做。”

然后开始：

- 做连接器；
- 做 ERP；
- 做 CNC；
- 做电源；
- 做测试仪器；

最后核心产品没人推进。

这恰恰违反了 SpaceX 自己反复强调的删除和聚焦逻辑。

正确问题不是“能不能自己做”，而是：

> **如果不自己做，我们最关键的反馈环会不会被卡住？**

如果答案是否定的，外购通常更合理。

## 8. 供应商也可以成为“半内部反馈环”

Make / Buy 不是二元。

优秀供应商合作可以做到：

- 小批量；
- 快速 DFM；
- 工程师直接沟通；
- 共享 process data；
- 快速 revision；
- 预留产能；
- 共同维护关键参数和异常记录。

如果能做到这些，外部供应商一样可以进入快速 loop。真正要优化的是**反馈时间和信息损失**，不是公司边界本身。

## 9. 医疗器械特别注意

医疗器械供应商往往同时承担：

- 特殊材料；
- 洁净；
- 灭菌；
- 植入级资质；
- process validation；
- traceability。

因此“自己做更快”可能在研发阶段成立，但到受控生产阶段反而增加验证负担。

一个常见的合理路径是：

1. 早期内部快速做原型，关闭关键工程未知；
2. 设计逐步稳定后，把需要资质和稳定过程能力的环节交给合格供应商；
3. 保留图纸、关键参数、检验方法、异常数据和变更权，不把产品知识一起外包。

Make / Buy 必须把**法规、供应商质量体系和未来验证成本**一起算进去。
